## Open questions

- **Dockerfile not in inventory.** Both `action.yml` (`runs.image: Dockerfile`) and `docker-compose.yml` (`build: .`) reference a Dockerfile that is not listed in the inventory, so the container base image, Chromium version and Python version installed for the action are not documented here.
- **No dependency manifest in inventory.** There is no `requirements.txt` / `pyproject.toml` / `setup.py` in the inventory; the exact pinned versions of PyGithub, BeautifulSoup, lxml, selenium and webdriver-manager are unknown.
- **Hidden files / other content not in inventory.** The README references `.nojekyll` and a `CHANGELOG.md`; the weather README references a `.gitignore`; `_sidebar.md` links to many pages (`quickstart.md`, `themes.md`, `deploy.md`, etc.) — none are in the inventory, so their content is not documented.
- **Weather sample appears non-functional / internally inconsistent.** `script.js` uses a placeholder API key, ignores the five input fields, and targets `#weather-container` while `index.html` provides `#weatherResults`; the CSS also styles classes (`.weather-card`, `.city-name`, `.temperature`, `.description`) that the JS never emits (it emits `.city-weather` with `<h2>`/`<p>`). Whether this sample is intended to run at all is not clear from the code.
- **`Credly` hardcoded fallback username.** `credly.py` falls back to the username `pemtajo` when neither an argument nor `INPUT_CREDLY_USER` is set; the provenance of that default is not documented.
- **Selector fragility.** The scraper relies on generated/styled class names (e.g. `Cardstyles__StyledContainer-fredly__sc-…`, `EarnedBadgeCardstyles__…`) that change when Credly's front-end changes; no test covers this in the inventory.
- **`NUMBER_LAST_BADGES` truthiness quirk.** In `credly.py`, `NUMBER_BADGES = number_badges or NUMBER_LAST_BADGES or 0` treats an explicit `0` as falsy; it still resolves to `0` (no limit) here, but the pattern would drop any deliberately-falsy value.
- **CI lint globs are narrow.** `ci.yml` lints only `README.md`, `CHANGELOG.md`, `RELEASE_CHECKLIST.md`; the other markdown pages in the inventory are not linted by the workflow as configured.
- **Action reference tag.** The README documents a stable `v1` tag, but no workflow in this inventory references `@v1` (they use `uses: ./` or versioned marketplace actions), so the tag's current target is not verifiable from the inventory.
